# ดอยดาว คาเฟ่ · Back Office (demo)

Back Office demo for a made-up coffee chain, **ดอยดาว คาเฟ่ (Doi Dao Café)**. It is built the same
way as the เพื่อนเรียน Back Office: a Nuxt 4 SPA (`ssr: false`) whose list and detail pages
come from one config file per entity. This copy needs nothing else to run. The UI kit, field
validation and mock repositories that เพื่อนเรียน gets from `@philaphat-2003/pheuan-*` packages
are copied into `app/ui` and `app/lib`.

The `§` numbers in code comments point to the design spec in
`pheuan-rian-backoffice/docs/backoffice-design-spec.md`. This demo follows the same rules.

## Run

Requires Node ≥ 22 and pnpm 10.

```sh
pnpm install
pnpm dev          # http://localhost:3002
```

| Script           | Does                                                        |
| ---------------- | ----------------------------------------------------------- |
| `pnpm dev`       | dev server on :3002                                         |
| `pnpm build`     | production build (`node .output/server/index.mjs`)          |
| `pnpm generate`  | static files for any static host                            |
| `pnpm typecheck` | `nuxt typecheck`                                            |
| `pnpm lint`      | ESLint + Prettier check                                     |
| `pnpm mocks`     | regenerate `app/mocks/*.json` (dates count back from today) |

## Demo data

All data is mock data, served from `app/mocks/*.json`. Edits persist in `localStorage`, so clear
site data to reset. Sign in with `admin@doidao.cafe` / `cafe1234`. The login page also has
one-click buttons for each role:

| Role   | Can                                           |
| ------ | --------------------------------------------- |
| admin  | everything, including Settings                |
| editor | create / edit / delete / publish, no Settings |
| viewer | read only                                     |

Set `NUXT_PUBLIC_MOCK_ERROR=true` to make every call fail and see the error states.

## What it manages

| Menu            | Entity       | Highlights                                                      |
| --------------- | ------------ | --------------------------------------------------------------- |
| ภาพรวม          | dashboard    | today's orders and revenue, rush hours, channels, best sellers  |
| วิเคราะห์ยอดขาย | analytics    | 7 / 30 / 90-day revenue, bill size, hot / iced / blended, waste |
| ออเดอร์         | `orders`     | dine-in, takeaway, Grab, LINE MAN                               |

| หมวดเมนู        | `categories` | order and emoji of the POS groups                               |

| สมาชิก          | `members`    | loyalty tiers, points, birthday-this-month card                 |
| รีวิว           | `reviews`    | reply and show / hide on the website                            |
| สาขา            | `branches`   | hours, seats, today's numbers                                   |

## Structure

```
app/
  config/entities/   one file per entity → list + detail pages, no new components
  config/settings.ts settings categories → /settings/:category (tabs)
  components/        ListPage, DetailPage, RecordForm, FieldInput, dashboard charts
  composables/       useRepos, useCan, useRecordForm (edit mode + validation), useLeaveGuard, …
  ui/                UI kit (ported from pheuan-ui): Sidebar, DataTable, StatCard, Mascot, …
  lib/types.ts       Zod schemas of every table
  lib/core/          field types, roles, list query (filter / sort / page in the URL)
  lib/api/           repository interfaces + localStorage mock
  mocks/             seed JSON (generated by scripts/generate-mocks.mjs)
i18n/locales/        th.json / en.json
public/              login photo, menu thumbnails (generated)
```

To add an entity:

1. Add a schema to `app/lib/types.ts`.
2. Add a table to `app/lib/api/factory.ts` and seed data to `app/mocks/`.
3. Write `app/config/entities/<key>.ts` and list it in `app/config/entities/index.ts`.
4. Add its strings under `entities.<key>` and `nav.<key>` in both locale files.
